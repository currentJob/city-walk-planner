# 셀프 호스팅 배포판과 참여 제한 IP 수정

사용자 요청: 다른 사람이 도커만 받아 자기 도메인에 바로 배포할 수 있게 한다. 백엔드는 uvicorn + SQLite 로 한다(선택). 함께 wrangler 버전을 고정한다(별도 커밋 `69f9809`).

## 발견한 버그: 참여 제한이 전체 사용자에게 공유됨

- `api/ratelimit.client_ip()` 는 소켓 주소만 본다. 프록시나 엣지 뒤에서는 모든 요청이 앞단 하나의 주소로 보여서, "IP 당 10분 10회" 초대코드 참여 제한을 **모든 사용자가 나눠 쓰게** 된다. 운영 중인 Cloudflare Worker 와 로컬 Docker(nginx) 모두 해당했다.
- 수정: `CWP_CLIENT_IP_HEADER` 로 **앞단이 직접 덮어쓰는 헤더** 하나만 믿게 했다. 설정하지 않으면 기존대로 소켓 주소를 쓴다.
  - Cloudflare Worker: `CF-Connecting-IP` (`wrangler.jsonc` vars, entry `ENV_KEYS`)
  - 로컬 Docker: nginx 가 `X-Real-IP $remote_addr` 로 덮어쓰고 api 가 그 헤더를 믿는다.
  - 셀프 호스팅: uvicorn `--proxy-headers --forwarded-allow-ips '*'`. 앱 포트는 외부에 열지 않고 Caddy 만 닿는다.

## 셀프 호스팅 구성

- `docker/app.Dockerfile`: `python:3.12.14-slim-bookworm` + uv 0.12.20. `uv sync --frozen --no-dev` 로 설치하고 uid 10001 사용자로 실행한다. 데이터는 `/data`, health check 는 `/api/health`. 화면(`web/`, `apiBase` 빈 값 = 같은 출처)과 API 를 함께 준다.
- `docker-compose.selfhost.yml`: `app` + `caddy:2.11.4-alpine`(`caddy reverse-proxy --from $DOMAIN`, 인증서 자동 발급). 이 파일 하나만 있으면 되고, 프로젝트 이름을 `city-walk-planner-selfhost` 로 분리했다(개발용 스택과 네트워크를 공유하던 문제).
- `.github/workflows/image.yml`: main push 와 `v*` 태그에서 `ghcr.io/<owner>/city-walk-planner` 로 올린다(`latest`, 커밋 SHA, 태그). 액션은 `setup-buildx-action@v4.4.1`, `login-action@v4.6.0`, `build-push-action@v7.4.0` 으로 고정했다.
- README "셀프 호스팅" 절: 실행, 백업, 복원 방법.

## 주의

- Worker 시작 시간이 967ms 로 한도 1초에 가깝다(이전 820ms). 코드나 의존성이 늘면 배포가 거부될 수 있다(오류 10021). 줄이려면 가져오기를 지연하거나 큰 모듈을 나눈다.
- GHCR 패키지는 처음 올리면 비공개다. 다른 사람이 받으려면 GitHub 에서 공개로 바꿔야 한다.
- 도커의 포트 포워딩 방식에 따라, 리눅스 서버에서도 접속 주소가 도커 게이트웨이로 보일 수 있다(userland-proxy). 그 경우 제한이 다시 공유된다. 실제 서버에서 `join_attempt.ip` 를 한 번 확인한다.
