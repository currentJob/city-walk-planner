# 포트폴리오 연결과 영수증 경비 입력

사용자 요청:
- 포트폴리오의 '데모'를 '개인 프로젝트'로 바꾼다.
- GitHub Pages 에 배포한 프로젝트들을 서로 연결한다.
- 영수증 OCR 결과로 경비를 입력하게 한다.

세 단계를 순서대로 진행했다. 필요한 저장소는 직접 clone 했다(`projects/yolov8-seg-page`, `projects/ocr-llm-page`, 워크스페이스 목록에 등록).

## 1. 포트폴리오 (portfolio-github-pages `2d733c6`)

- 섹션 이름을 "개인 프로젝트"로 바꾸고 카드 제목에서 '데모'를 뺐다.
- 링크 문구는 "사이트 열기"로 바꾸고, "소스 보기"(GitHub 저장소, 네 저장소 모두 공개)를 추가했다.
- README 에 개인 프로젝트 목록을 넣었다. 테스트 5개, 빌드 통과.

## 2. 사이트 사이 연결

- 세 사이트 상단에 같은 모양의 바를 넣었다. 왼쪽은 "← currentjob 포트폴리오", 오른쪽은 세 프로젝트 링크이고 현재 사이트는 굵게 표시한다.
  - YOLOv8 `3083e19`, OCR `896b61e`, 이 저장소 `99e7d1c`
- YOLO 는 화면 높이를 꽉 채우는 배치라 높이에서 34px 를 뺐다. 페이지 제목·설명·`lang="ko"` 도 정리했다.
- 이 저장소에서는 `currentjob.github.io` 에서만 바를 보인다(`showAuthorBar`). 셀프 호스팅 사본에는 작성자 표시가 나오지 않는다.
- 외부 도메인 허용 목록에 `currentjob.github.io` 를 추가했다. 링크일 뿐이고 자산을 받지 않는다.

## 3. 영수증 사진으로 경비 입력

- **OCR 프로젝트** (`77d513b`)
  - 앱의 OCR 파이프라인을 ES 모듈 `lib/korean-ocr.mjs`(81KB)로도 빌드한다(`vite.lib.config.ts`).
  - 모델·사전·wasm 은 그 사이트의 파일을 절대 주소로 받는다. GitHub Pages 가 CORS `*` 를 주는 것을 확인했다.
  - lib 모드는 wasm 을 base64 로 박아 34MB 가 되어, 일반 빌드 + 진입점 방식으로 바꿨다.
- **이 저장소**
  - `js/receipt.js`
    - `readReceipt(file)`: 모듈을 한 번만 불러 사진을 읽는다.
    - `parseReceipt(items)`: 같은 높이의 조각을 한 줄로 묶는다. 금액은 합계/TOTAL 줄에서 찾고(소계·부가세·서비스·거스름·카드 줄 제외), 없으면 가장 큰 소수 금액을 쓴다. 날짜는 연-월-일과 일/월/년을 읽는다. 상호는 위쪽 줄에서 찾는다. 못 찾은 값은 비워 두고 지어내지 않는다.
  - 동행 페이지 경비 폼에 "영수증 사진으로 채우기"를 추가했다.
    - 진행 상태를 보여 주고, 결과는 입력 칸만 채운다. 저장은 사용자가 확인한 뒤 누른다.
    - `CWP_CONFIG.ocrModule` 이 비면 버튼이 나오지 않는다. Pages 는 `CWP_OCR_MODULE`(기본값 위 모듈)을 굽고, 로컬·셀프 호스팅 기본값은 빈 값이다.
  - 경비 폼이 동기화 때 다시 그려지면서 쓰던 값이 사라지던 문제도 고쳤다. 그리기 전에 값을 읽어 되살린다.

## 검증

- PASS 이 저장소 `pytest` 935 passed(영수증 해석 4개 추가), ruff, `.github/quality/gate.py` 4/4.
- PASS OCR 프로젝트 `npm run build`. 앱 빌드와 `dist/lib/korean-ocr.mjs` 가 나온다. 배포 후 `lib/korean-ocr.mjs` 가 200, `text/javascript`, `Access-Control-Allow-Origin: *` 로 응답했다.
- PASS 다른 출처(localhost:8093)에서 배포된 모듈을 불러 그린 영수증을 인식했다. 모델 로드 6.8초(첫 회), 인식 7.3초(데스크톱 헤드리스, WASM 단일 스레드).
- PASS 동행 페이지 전체 흐름(로컬 서버, 테스트 여행 생성, 설정을 잠시 로컬 모듈로 바꿔 확인 후 되돌림): 버튼 표시 → "모델 준비 중" → 금액 74.00, 메모 "LAN FONG YUEN" 채움.
  - 그 사진의 날짜는 OCR 이 "0010/202" 로 잘못 읽어 비워 두었다(지어내지 않음 확인).
- PASS 세 사이트 상단 바: 데스크톱·모바일 캡처, 높이 34px, YOLO 화면 넘침 0.
- 기존 문제(이번 변경과 무관): YOLO·OCR 저장소의 `npm run lint` 오류 7개·26개는 손대지 않은 파일에 있고, 배포 워크플로는 lint 를 돌리지 않는다.
- 한계
  - 휴대폰에서 첫 사용 때 모델 약 30MB 를 받고 인식에 10초 이상 걸릴 수 있다. 실기기에서는 재지 않았다.
  - 실제 영수증 사진으로는 시험하지 않았다(그린 영수증만).
